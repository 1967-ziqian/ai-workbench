# 身份

## 一、这是什么

一个**缩小版的工作台框架**，专门存「解决新问题的方法」（向前解题，区别于复盘）。

一个条目 = 一个自包含的 `.md` 文件 + 一份 frontmatter 身份契约。两种消费者：

- **人**：工作台「方法库」页面（左目录按类型分组、可折叠；右正文先身份卡再全文）。
- **AI**：直接读这批 `.md`，按 frontmatter 判断「该不该用」，零隐藏依赖，谁来读都一样套用。

**同一份源，两端不打架**——不是「页面一份、给 AI 一份」，是同一批文件。

## 二、工作台怎么读这批 .md

- 场景配置：`plugins/luanyujia-shell/scenarios/method-library.json`，`root` 指向本目录。
- 渲染：`renderer/app.js` 的 `renderMethodLib`。
- 页面行为：
  1. **递归**扫 `方法/`、`自动化/`、`素材/` 与根目录的 `.md`；
  2. 按 frontmatter 的 `type` **分组**（方法 / 自动化 / 素材 / 文档），组标题可**折叠展开**；
  3. 折叠状态记在该面板自己的 state 里（键＝面板 id＋组名），不写进工作台全局配置；
  4. 右侧正文 = 身份卡（名称 / 何时用 / 何时不用 / 出处 / 最后核对）+ 全文。
- **目录是给人的直觉，`type` 是给页面的分组键**，两个独立维度，缺一个都会乱。

## 三、目录与命名约定

```
方法库/
├─ _INDEX.md      发现入口（AI 只从这里进）
├─ 身份.md        这份
├─ GLOSSARY.md    共享词表
├─ AGENTS.md      AI 读法契约
├─ 设计框架.md    框架设计（分层、类型判据、规则）
├─ 方法/          type: method  —— 有顺序与判断点的大体系
├─ 自动化/        type: automation —— 一条命令能独立跑的小工具
└─ 素材/          type: material —— 只存产物，可整版替换
```

- 方法步骤文件统一命名 `框架-N-名字.md`（N=1..5），内容型方法直接用方法名（`question-master.md`、`女娲蒸馏.md`）。
- 自动化文件统一命名 `A<N>-名字.md`（N=1..6）。
- **frontmatter 必填**：`name`（唯一键）/ `title` / `type` / `description` / `triggers` / `when-not` / `source` / `最后核对`（YYYY-MM-DD）。
- `type` 只有三种：`method` / `automation` / `material`。**一个文件不许兼两型。**
- 新术语先查 `GLOSSARY.md`，没有再补一条——别造同义多词。

## 四、边界（什么不进库）

- **失败教训 / 踩坑** → `../self-review/错题册.md`（带状态机：已验证 / 待验证 / 已挂载）。库只存向前的解题方法。
- **DSH 个性化插件/工具**（`ds_*`、`plugins/dsh-ops`）→ 其他 AI 无法调用，**留本地，不进库也不进 `_INDEX`**。
- **已有成熟 skill 能直接做的事** → 直接用 skill，不绕一圈再造方法。
- 依赖本机环境的能力（DSH 引擎、浏览器窗口）**可以进库**，但要在正文里写明「参考实现」与「无此环境跑不了」——**文档可共享，脚本不外传**。
