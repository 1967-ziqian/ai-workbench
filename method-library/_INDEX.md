# 方法库（Method Library）

> **这是索引，不是目录。** 每行自带 triggers / when-not / 依赖——AI 只读这张表，命中才点开对应文件，**不要遍历目录**。

## 一句话
一个**缩小版的工作台框架**，专门存「解决新问题的方法」（向前解题，区别于复盘）。一个条目 = 一个自包含 `.md` + 一份 frontmatter 身份契约。人看工作台「方法库」页面，AI 直接读这批 `.md`——同一份源。

## 怎么用（四步）
1. **发现** → 读这张表，按 triggers 初筛候选。
2. **判命中** → 逐条对 triggers / when-not；`when-not` 优先，命中就跳过。
3. **套用** → 照 `.md` 正文的顺序走，盯失效信号，下游要落到具体产物。
4. **留痕与回流** → 任务首行写 `判据｜命中索引：…`；坑进错题册，可泛化的成功变新条目。

详见 `AGENTS.md`（AI 读法契约）、`设计框架.md`（框架与判据）、`身份.md`（库是什么、页面怎么读）。

## 什么不进库
- 失败教训 / 踩坑 → `../self-review/错题册.md`。
- **DSH 个性化插件/工具**（`ds_*`、`plugins/dsh-ops`）→ 留本地，不进库也不进这张表。
- 已有成熟 skill 能直接做的事 → 不绕圈再造。

## 怎么加一条
1. 复制现有条目的 frontmatter 骨架，填 `name / title / type / description / triggers / when-not / source / 最后核对`。
2. `type` 三选一（method / automation / material），**一个文件不许兼两型**。
3. 放进对应目录：`方法/` / `自动化/` / `素材/`。
4. **在这张表补一行**：名称 + triggers 一句 + when-not 一句 + 路径 + 依赖——只写名字等于没登记。
5. 新术语先查 `GLOSSARY.md`。
