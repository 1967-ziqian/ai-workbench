# A2 哨兵复查挂钩

## 这条为什么存在
复盘「已验证」门槛需要真实复查记录支撑，否则门槛恒空转。把复查挂到哨兵上，会话一变就顺手跑，零人工、零额外 token。

## 入口命令
```bash
pythonw tools/ds_sentinel.py     # 后台常驻，无窗口
```
（挂钩本身没有独立命令——它是哨兵主循环里的一步。）

## 输入
- 工作台会话落盘文件的变化事件。
- 复盘模块的使用记录（判断某条目是否「复发/漏提醒」）。

## 输出
- 复查记录写入 `复盘/使用记录.jsonl`（带「条目 + id」关联）。
- 一天最多弹一次提醒；心跳文件 `上下文/哨兵-心跳.txt` 带 `pid=`。

## 退出码含义
- `ds_sentinel.py` 无显式退出码，正常常驻（`sys.exit` 只在缺 `zstandard` 依赖时触发）。
- 哨兵**不该有自退路径**：心跳一停就是被外部杀掉，别去代码里找 bug。

## 步骤
1. 主循环前 `import recheck` 的相关函数（**零新进程**，不 spawn 子进程）。
2. 检测到会话落盘变化 → 调 `recheck_tick()`：跑复查，把「命中索引且真读了」的轮记成复查记录（带条目 id）。
3. 容错：recheck 坏掉**不打断**哨兵主功能（import 用 try 包住）。
4. 节流：300 秒一次；一天最多弹一次提醒。
5. 心跳 `beat()` **强制带 `pid=`**——心跳文件是覆盖写的、只留最后一条，缺 pid 会让启动器把活着的哨兵判成死的，起第二个。

## 验收
`python tools/test_sentinel_recheck.py` → 11 条断言全绿。
**判活不能只看 pid**（pid 会被系统回收复用）：要 pid 存活 + 心跳 90 秒内 + 心跳里的 pid 对得上。

## 参考实现（本地）
- `tools/ds_sentinel.py`：`recheck_tick()`、带 `pid=` 的 `beat()`。
- `tools/recheck.py`：写复查记录（带条目 + id），`--dry-run` 不落盘、打印跳过原因。
- `tools/test_sentinel_recheck.py`：11 条断言自证。
