# A5 网页 AI 调用

## 这条为什么存在
工作台外壳（Electron）开了 `--remote-debugging-port=9222`，每个网页 AI 窗口都是一个 CDP target。脚本并发向多家**已登录**网页 AI 发问、抓答——等于白用几家模型的算力，还能按任务类型挑最合适的站。

## 入口命令
```bash
python webai_ask.py "你的问题"                    # 五家并发
python webai_ask.py "问题" kimi deepseek          # 指定几家
python webai_ask.py -f 问题.txt                   # 问题从文件读
python webai_ask.py "问题" --wait 180             # 加长等待
python webai_ask.py "问题" --force                # 跳过 180 分钟去重
```

## 输入
- 问题文本（或 `-f` 的文件）。
- 站名（可选）：`kimi` / `deepseek` / `doubao` / `qianwen` / `chatglm`。**不写站名 = 五家全问。**

## 输出
- 结果落 `外包/<时间>-<问题前12字>.md`；终端只打印摘要，**全文进文件**（省上下文）。
- 去重记录：`外包/_dedup.json`（同问题同站 180 分钟内不重发，`--force` 可强发）。

## 退出码含义
- `webai_ask.py` 无显式退出码，正常结束返回 0。

## 步骤
1. **前置**：工作台外壳在跑，且目标网页 AI **窗口已打开并登录**——窗口没开会报「窗口未打开」。
2. 并发发问 → 轮询抓答 → 收工判据走 `settle_update`（见 A1，不另写一套）。
3. 落盘 `外包/`，终端出摘要。

## 坑（实测，别自己重踩）
- **千问风控**：连问几次会跳阿里 `punish` 验证页（iframe 420×320）。脚本会明确报「需要人机验证，请手动完成」，**不会误报成「没发出」**；过完验证继续能用。→ 千问适合单次问，别连着刷。
- **网页版 ≠ App**：站内/实时/需登录的题别派网页 AI。网上说的独家数据源（豆包查抖音、千问下单淘宝）是 App 能力，**对话框里不兑现**。
- **后台窗口 `innerText` 读成空**：五个窗口只有一个能在前台，其余 `visibility:hidden`，`innerText` 返回空但 `textContent` 正常。抓文本一律先 innerText 再退 textContent——这是「每次调网页 AI 都卡很久 + 重复提问」的真正原因。
- **只取最后一块新增内容**：豆包会把「上一轮答案 + 追问建议」重新渲染，指纹一变就算新块，拼多块＝把上轮答案带回来。
- **不要用 `--help` 之类开关试用法**：不认识的参数以前会被当成问题真发出去（已修）。
- **五站并发时**，各站耗时不同（3.4–5.6s），别按固定秒数假设。

## 派站规则（按任务类型，不按谁更强）
| 任务 | 派谁 |
|---|---|
| 代码推理、要行号、要实测值 | DeepSeek |
| 长文档 | Kimi |
| 中文措辞 | 豆包 |
| 学术 | 智谱清言 |
| 电商办事 | 千问 |

## 验收
- `外包/` 里有新文件，且内容不是提问原文、不是思考链、不是上一轮答案。
- 智谱的回答里不含 `text-advance-thinking-con` 思考容器的内容。

## 参考实现（本地）
- `webai_ask.py`：入口、站点分发、去重、风控探测（`CHECK_VERIFY_JS`）、收工判据。
- `webai_multi.py`：CDP 协议层（找 target、聚焦、输入、抓取选择器 `GRAB_SEL`）。

## 其他 AI 复用须知
依赖本机工作台外壳 + 已登录的网页 AI 窗口，**无此环境跑不了**。文档可共享，脚本不外传。
