# 进度

> **核心价值（先读这条）**：记进度第一目的**不是**"放索引"或"交接状态"，是**防重复劳动**——避免「明明做过的事，又因为没人记得、查不到，被重做一遍」。历史教训就是反复造轮子、重复消耗 token。本台账必须能被**动手前检索**才是真有用；只事后记、事前不查，等于没建。

## 一、为什么单独一块，不进方法库条目

目录 / 守则 / 身份是**静态框架**（一次写定、偶尔刷新）；进度是**动态记录**（每次任务追加）。两者性质不同，所以进度不进 `方法/` `自动化/` `素材/`，落单独的台账文件。

## 二、落点

`进度台账.md`

## 三、强制规则（靠意愿必漏，且必须两端都做）

光写进这份文档没用——必须落进 `AGENTS.md` 第四步 + 由轻路由 skill 兜底触发，才算"强制"。规则分**两端**，缺一不可：

### 端 A · 动手前查重（防重做的关键）
任何 AI 接到任务、**动手前先 grep 本台账**（按任务关键词 / 关联文件），确认这事：
- **没做过** → 正常做；
- **做过但没完** → 接着做，不重做；
- **做过且完** → 直接复用产出，别再造一遍。
不查就动手 = 主动制造重复劳动。

### 端 B · 结束后记一笔
任务结束向台账**追加一条**（格式见下）。不写等于这次工作没留痕，下个 AI 接手时两眼一抹黑，又会重做。

每条字段：
- **日期时间**
- **哪个 AI / 实例**（区分不同 AI，避免混写）
- **任务**：这次干了什么
- **关键词 / 关联**：便于检索去重的核心词 + 关联文件/方法（如 `方法库重组`、`renderMethodLib`）
- **产出物**：路径（文件 / 代码 / 文档）
- **状态**：进行中 / 已完成 / 阻塞（阻塞要写卡点）
- **下一步 / 待确认**：谁接、要什么

## 四、与复盘的区别（别混）

- **进度**（本块）：记"事"——做了啥、到哪了、带关键词便于查重；第一目的是**防重复劳动**。
- **复盘**（`../self-review/错题册.md`）：记"坑"——失败教训、已验证/待验证。

一件事如果既产出进展又暴露坑，**两边都记**：进度记事（带关键词），复盘记坑，各归各。

## 五、为什么必须强制，不能靠自觉

历史教训：把"读索引""写留痕"当自觉动作，结果就是 AI 在简单任务、新会话、任务密集时全部跳过——然后同一件事被做第二遍、第三遍。凡是依赖 AI 自觉的动作，必须变成机制——文件写死规则 + skill/hook 兜底触发。本块规则和 `AGENTS.md` 第四步、轻路由 skill 三处同时锁，才不至于又变成"写下≠生效"。
