# 框架-算量先定口径

## 这条为什么存在

2026-10-27 两次算错槽位余量：拿文件字节充当渲染字节、边界头扣两遍，得出 114 / 59，实测 103。同日 S2 百分比分母错用名义值，显示 84% 时实际 96%，软限告警失效。2026-10-28 计数层复发：体检.jsonl 4228 行去重后仅 1129，虚高 3.7 倍——直接拿日志行数当违规率。

根因一致：**没先问「这条判据比的到底是哪一段」，就动手算；对同一段扣两次 = 虚报风险。**

## 怎么做

算任何量化指标前，先写一句「**判据作用在：正文 / 渲染 / 文件 / 计数段**」，再确认分母是谁。同一段不许扣两次。口径写在被算的东西旁边，不写在脑子里。

- **体积**：明确比的是「文件 / 渲染 / 正文」哪一段，边界头只扣一次
- **百分比**：分母用实际值，不用品名值
- **计数**：任何「日志行数」先用唯一键去重，再去算率

## 反例

- 拿 `maxBytes - 160` 算余量，把 160 里已含的头又算一遍
- 拿体检.jsonl 原始行数 4228 当「违规 4228 条」
- S2 显示 84% 时实际已 96%，软限告警形同虚设

## 不适用

只有一段可比、不存在多段口径的地方（如数一个纯文本文件的行数）。
