# 框架·3 套用

## 这步为什么存在
方法的价值全在正文那套顺序和判断点上。**照着走**和**凭印象重做**是两个完全不同的结果——后者等于没读方法，还多花一遍时间。

## 顺序
1. **先读整篇**，别只读一半。方法文件都短，读全比读一半再回头补便宜。
2. **按正文的顺序走**，不要打乱顺序重排——顺序本身常常就是方法的一部分。
3. **遇到判断点就停下判断**，把判断依据写出来（依据是什么、命中哪条判据）。判断点不写依据 = 没判断。
4. **盯失效信号**：正文里写明的「什么情况下这条不成立/要停」，出现了就按它说的处理，不要硬撑。
5. **看上下游两栏**：上游输入齐不齐、下游输出是否落到具体产物（一个文件、一段结论、一个可执行的下一步）。
6. **产出下游**：不产出等于没套用。

## 判断点
- 正文与当前情况对不上 → **停下**，别硬套。回「框架·2 判命中」重新判断，或换一条。
- 正文要求的前置条件没满足 → 先补前置，别跳步。
- 中途发现这方法的假设不成立 → 记进复盘错题册（这是回流的最有价值来源）。
- 方法给了判断点但当前信息不够判断 → 明确说"缺 X"，去问/去查，别猜一个然后当结论用。

## 失效信号
- 执行完说不出"因为正文第几步我才这么做" → 这是在凭经验，不是套用。
- 产出是"应该可以了"而不是具体东西 → 下游没落地。
- 跳过一半步骤还交付了 → 方法被当参考而非流程，失效。

## 上游输入 / 下游输出
- 上游：一条已确认可用的条目（来自「框架·2 判命中」）。
- 下游：具体产物 + 执行中发现的坑 → 交给「框架·4 留痕与回流」。
