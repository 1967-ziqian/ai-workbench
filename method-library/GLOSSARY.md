# 共享词表（GLOSSARY）

跨条目统一术语。新增条目时先查这里，避免同一概念多种叫法。

| 术语 | 含义 | 来源 |
|---|---|---|
| 方法（method） | 本库里一条可携带的解题套路，一个 `.md` 文件 | 方法库 |
| 自动化步骤（automation） | 本库里独立、可移植的小工具：**一条命令能独立跑**（有入口/退出码/输出） | 方法库 |
| 素材（material） | 只存**产物**（prompt 集、清单），可整版替换；不是方法 | 方法库（2026-10-28 新增） |
| 类型（type） | frontmatter 里的 `method` / `automation` / `material`；**一个文件不许兼两型** | 方法库 |
| 触发（trigger） | 决定「该不该用这条方法」的信号，写在 frontmatter | Matt skills |
| 身份（identity） | frontmatter 里的 `name / description / triggers / when-not` 等，即「发现机制」 | Matt skills |
| 发现（discovery） | 从索引找到候选条目的那一步 | 方法库框架-1 |
| 判命中 | 用 triggers/when-not 做语义匹配，决定用不用；**when-not 优先** | 方法库框架-2 |
| 套用（apply） | 照方法正文的顺序与判断点走，盯失效信号 | 方法库框架-3 |
| 留痕 | 任务首行写 `判据｜命中索引：…`，命中写条目名、不命中写「无」 | 方法库框架-4 |
| 命中索引 | 留痕那一行里声明"这次查了/用了哪条"的值 | 方法库框架-4 |
| 回流 | 把坑回错题册、把可泛化的经验回成新条目 | 方法库框架-4 |
| 判断点 | 方法正文里需要停下来做判断的岔口；判断必须写依据 | 方法库 |
| 失效信号 | 什么情况下这条方法/步骤不成立、该停 | 方法库 |
| 上游输入 / 下游输出 | 方法的接口：吃什么、吐什么；吐不出具体东西等于没套用 | 方法库 |
| 鉴别力反证 | 回归测试里专门证明"旧口径必须提前收工"的那条断言，防止有人改回旧口径而不自知 | A1 |
| 漏斗（funnel） | 把模糊输入逐步逼到可执行输出的纵向流程 | question-master |
| 质量门（gate） | 进入执行前必须通过的校验清单 | question-master |
| 红蓝对抗 | 红队挑刺、蓝队防御，逼出必须修的问题 vs 可接受局限 | prompt-upgrader |
| 掘根 | 用 5 Whys 追问「为什么重要 / 不解决会怎样 / 背后更大的问题」 | 四视角 |
| 翻转 | 从正 / 反 / 侧三视角重述问题，防单一视角盲区 | 四视角 |
| 向前解题 | 解决「还没发生过」的新问题，区别于复盘 | 本库约定 |
| 复盘 | 对已发生失败的归并、提炼、验证，归入复盘模块 | 本库约定 |
| 共存（coexist） | 方法 / 自动化 / 素材各自独立文件、独立身份，不互相吞并 | 方法库 |
| 工程师（engineer） | 本库框架的血缘来源——Matt Pocock 的技能体系（横向技能库 + frontmatter 发现机制） | Matt skills |
| 马斯克五步 | 马斯克工程五步法，改写为「四问定动作」：该不该有→能不能少一步→能不能换人/机器→能不能更快；**自动化是最后一步** | 复盘模块 |
| 四问定动作 | 马斯克五步的改写版，见 `方法/框架-5-四问定动作.md` | 方法库框架-5 |
| 参考实现（reference impl） | 某自动化步骤在本工作区已有的本地脚本/实现，仅供参照；步骤本身可移植，不依赖它 | 方法库 |
| 记下≠生效 | 写了/记了不等于真起作用；必须有能跑出来的证据（如 fixture 断言） | 本库约定 |
