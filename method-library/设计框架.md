# 设计框架

> 这份只写**框架层**的结构与规则。**每一步的具体阐述在各条目自己的文件里**（`方法/框架-1..5`），这里只留指针，不重复写——同一件事写两遍，改一处就漂。

## 一、分层

| 层 | 文件 | 职责 |
|---|---|---|
| 框架层 | 本文件 | 分层、类型判据、与 skill 分工、发现与留痕机制 |
| 身份层 | `身份.md` / `GLOSSARY.md` / `AGENTS.md` / `_INDEX.md` | 这库是什么、怎么被发现、AI 怎么读 |
| 步骤层 | `方法/*.md`、`自动化/*.md` | **每个具体步骤各自成篇**，可单独优化、单独融合别的方法 |

步骤层为什么要拆：框架只有一份，改一处容易只改半边；拆开后每步能独立长、独立被别的方法引用。

## 二、三种类型（判据 + 硬约束）

| 类型 | 判据 | 落哪 |
|---|---|---|
| **automation** | **可独立套用的复用步骤**：或一条命令能独立跑（有入口/退出码/输出），或一条原则/规则（触发即按流程或清单自检，无脚本） | `自动化/` |
| **method** | 只有**顺序与判断点**，靠语义判断，没有可调用入口 | `方法/` |
| **material** | 只存**产物**（prompt 集、清单、素材），可整版替换 | `素材/` |

**硬约束：一个文件不许兼两型。** 兼了就会出现「改一处要动两处」——方法正文里塞脚本，或自动化文件里写半段判断。

**`contains` 字段废掉。** 没有任何代码读它，写了就是「记下≠生效」的又一条。改用两处可见：
- `_INDEX.md` 里加一列 `依赖：A2,A5`；
- method 正文写「上游输入 / 下游输出」的具体路径。

## 三、与 skill 的分工

- **每轮都要看见** → skill（如"去AI味"、幕布格式、教案排版）。
- **遇到某类问题才查** → 方法库。
- **同一内容只许一个落点。** 迁移进库后，skill 侧只留一行指针（见 `方法/女娲蒸馏.md` 的「skill 侧指针」段），正文不再双份维护。

## 四、发现机制

1. AI 从 `上下文/S3-索引/_默认.md` 知道**有**这个库；
2. 进 `_INDEX.md` —— **只读这一行索引**，不遍历目录；
3. `_INDEX.md` 每行必须自带 `triggers` 一句 + `when-not` 一句 + 路径 + 依赖。**只写名字的索引等于没有索引**（AI 还得逐个打开读 frontmatter，成本爆炸，然后就永远不会发生）；
4. 命中 `triggers` 才点开那个 `.md`；命中 `when-not` 直接跳过。

## 五、留痕机制

- 任务首行写：`判据｜命中索引：方法库/无`（命中写具体条目名，没命中写「无」）。可 grep 统计命中率。
- **写这句是 AI 的输出，自动不了**；但**检查它有没有写、写了有没有真读，可以自动化** → 见 `自动化/A6-命中留痕检查.md`。
- 框架层其余各步（发现、判命中、套用、四问定动作）都依赖语义判断，保持 method，不硬套自动化。

## 六、指针（框架层只留这一行）

- 四问定动作（马斯克自动化：该不该有 → 能不能少一步 → 能不能换人/机器 → 能不能更快 → 自动化）→ `方法/框架-5-四问定动作.md`
- 发现 → `方法/框架-1-发现.md`
- 判命中 → `方法/框架-2-判命中.md`
- 套用 → `方法/框架-3-套用.md`
- 留痕与回流 → `方法/框架-4-留痕与回流.md`

## 七、什么不进库

- 失败教训 / 踩坑 → 复盘模块（`../self-review/错题册.md`）。
- DSH 个性化插件（`ds_*`、`plugins/dsh-ops`）→ 留本地，不进库也不进 `_INDEX`。
- 已有成熟 skill 能直接做的事 → 不绕圈再造。
